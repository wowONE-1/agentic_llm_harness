# Проверка и демонстрация ЧП1

Проверено 2026-11-06: Docker Desktop на Mac, Linux-контейнеры с Python 3.12.8.
Тестовый compose-проект запускался отдельно от пользовательского, затем удалён.
Основной работающий экземпляр не пересоздавался: исправления находятся в исходниках.
Для применения нужен `docker compose up --build --wait`; предварительно сохранить
нужные файлы /work, поскольку пересоздание sandbox очищает его tmpfs.

## Что проверено

- Сборка из исходников, запуск обоих сервисов и healthy healthcheck.
- 10/10 автономных тестов на Mac и 10/10 внутри Linux-контейнера.
- HTTP auth, конфликт сессий, идемпотентность, один финальный result,
  переподключение, CLI, cancel обычной process group, timeout, защита путей и symlink.
- Через протокол sandbox: Python 3.12.8 доступен командам, uid 10001, cwd /work.
- Синтаксис Python, корректный JSON и внутренние ссылки двух OpenAPI-схем.
- Реальная LLM через OpenRouter: итоговый прогон Б1–Б5 **5/5**.

Модель: `nvidia/nemotron-3-ultra-550b-a55b:free`, MEMORY_TURNS=2, MAX_STEPS=8.

## Простота и исправления

Runtime использует только стандартную библиотеку Python, два сервиса, три инструмента,
одну сессию и память двух полных ходов. Удалён дублирующий `main.py`; единственный
клиентский entrypoint — `python3 -m runtime.client`. Остальные каталоги нужны:
`runtime`, `baf`, `schemas`, `tests`, `scripts`, `docs`, `.github`.
Восемь ADR сохранены: они соответствуют перечню решений задания, а не лишним подсистемам.
`.venv` — локальное окружение; `.env` и `results` исключены из Git.

Исправлено: PATH команд (Python образа находится в /usr/local/bin), использование
GATEWAY_TOKEN из окружения раннером, отображение HTTP-кода сбоя провайдера без его тела,
диагностика проваленных чекеров, общая инструкция точечного редактирования.
Чекер B4 по-прежнему требует точного сохранения остальных байтов, включая последний LF.

## Сценарий показа с реальной моделью

1. `docker compose up --build --wait`, затем `docker compose ps`.
2. `python3 -m runtime.client connect`.
3. `python3 -m runtime.client chat 'Создай hello.py, который печатает hello, и запусти его'`.
4. `docker compose exec sandbox cat /work/hello.py` — файл находится в контейнере.
5. Показать события и итоговый result; объяснить цикл и память в `runtime/harness.py`.
6. `python3 -m runtime.client release` — завершает сессию и удаляет рабочие файлы.
7. `python3 -m baf.runner --mode quality --output results/demo-quality.jsonl`.
8. `sh scripts/ci.sh` — автономные тесты, включая cancel и reconnect.

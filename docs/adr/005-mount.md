# 005. Кандидат: SSHFS через обратный SSH-туннель

Статус: proposed для ЧП2; в v0 монтирования нет.

Клиент экспортирует выбранную папку через ограниченный SFTP, устанавливает обратный
туннель к серверу. Отдельный mount-компонент монтирует SSHFS, sandbox получает /work.
Нужен прототип с двумя машинами, проверкой reconnect, uid/gid и очищения mount.

| Вариант | Плюсы | Цена |
|---|---|---|
| SSHFS + reverse tunnel | Шифрование, проходит клиентский NAT | FUSE, зависшие операции при обрыве, кеши |
| WebDAV + rclone mount | HTTP-инфраструктура, простой экспорт | Семантика rename/locking и кеш записи |
| NFS поверх WireGuard | Близко к обычной ФС, производительность | VPN, права uid/gid, сложнее клиентская установка |

Выбор предварительный: переносимость клиента и разрешённые привилегии FUSE нужно
проверить. Монтирование делать вне непривилегированного workload. RO по умолчанию,
RW явно выбирает пользователь. `.git` и служебные пути закрыть на уровне экспорта,
а не только Python-тулов. На обрыв — fail run, запрет новых exec до восстановления,
ограниченный timeout I/O. Кеш пользовательских файлов на сервере после release удалять.
Это целевое поведение; сейчас оно не реализовано и не проверено.
